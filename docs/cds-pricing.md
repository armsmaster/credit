# Прайсинг CDS: конвенции, модель, CDS-кривые

Модуль CDS живёт в сервисе `credit` (`backend/services/credit/credit_service/cds/`) и решает три задачи:

1. цены для **лимитных заявок на СПФИ** (Мосбиржа, клиринг НКЦ): стандартный купон + upfront;
2. цена для **внебиржевых сделок со Сбером**: par-купон с даты сделки;
3. **ежедневная выгрузка** итогов в банковскую position keeping систему.

Модель — ISDA CDS Standard Model с конвенциями из «Спецификации прайсинга CDS»; модуль `cds/isda.py` —
порт эталонной реализации из спецификации, тесты (`tests/test_cds.py`) сверяют с ней все примеры
спецификации (график Мосбиржи, ребейт, PUF↔QS, бутстреп, контракт Сбера).

## 1. Откуда берётся CDS-кривая

Рынка CDS почти нет, поэтому CDS-кривая контрольного лица строится из его **кредитной кривой по облигациям**
(уровень 3 спецификации):

1. На hazard-кривой облигаций считаются модельные **par spread** стандартных контрактов СПФИ
   (дата сделки = дата кривой, сроки 6M…5Y, полугодовой ролл).
2. К ним прибавляется **базис CDS–облигация b(T)** по срокам — вручную в параметрах контрольного лица,
   по умолчанию 0.
3. **Последовательный бутстреп** кусочно-постоянной λ(t) на (T<sub>i−1</sub>, T<sub>i</sub>] по этим par spread
   с recovery R контрольного лица (по умолчанию — R кредитной кривой). Узел, которому нужна λ ≤ 0
   (слишком отрицательный базис или «перевёрнутая» кривая), исключается с предупреждением; кривая
   продолжается предыдущей λ.
4. По полученной кривой для каждого срока: par spread, **QS**, **PUF** при купонах 100 и 500 б.п.,
   дожитие, чистый RPV01, ребейт и полный график платежей.

Дисконтирование — кривая RUB из сервиса `curves`, та же, на которой построена кредитная кривая (узлы DF
сохраняются в её состоянии); при пересчёте после сохранения процентной кривой берутся новые узлы.

## 2. Когда пересчитывается

Пересчёт полностью автоматический:

| Событие | Что пересчитывается |
|---|---|
| сохранена кредитная кривая (текущая или задним числом) | CDS-кривые всех контрольных лиц на этой кривой (задача `credit.cds_recalculate`) |
| сохранена процентная кривая | CDS-кривые, у которых дата кредитной кривой не раньше даты процентной (задача `credit.cds_rates_changed`) |
| изменены параметры контрольного лица | его CDS-кривая |
| кнопка «Пересчитать» | одна кривая |

Текущая кривая хранится в `credit.cds_states`; ночью (задача `credit.archive_states`, 00:35) кривые прошлых
дат уходят в историю `credit.cds_history`. Пересчёт задним числом создаёт новую версию в истории с тегом
«изменение задним числом» в журнале. Ошибка пересчёта CDS не мешает сохранить исходную кривую — она видна
в фоновых задачах.

## 3. Конвенции

| | СПФИ (`SPFI_STD`) | Сбер (`SBER_OTC`) |
|---|---|---|
| Дата начала срока E | T + 1 рабочий день | T |
| Начало первого периода | предыдущая CDS-дата (20.03/06/09/12), сдвинутая «Следующий» | E (короткий первый период) |
| Ребейт | да: продавец возвращает купон с начала периода до E | нет |
| Купон | стандартный (100 или 500 б.п.) + upfront | par spread сделки, upfront нет |
| Плановая дата прекращения | стандартная: CDS-дата после E + срок, полугодовой ролл (20.06/20.12) | любая дата |
| Последний период | включает Плановую дату прекращения | включает (настройка) |
| Даты платежей | CDS-даты, «Следующий» по календарю | то же |
| Календарь | СПФИ (= Москва + дни без клиринга НКЦ) | Москва |

Доля года купона и ребейта — ACT/ACT (ISDA): дни каждого календарного года делятся на длину этого года
(можно переключить на ACT/360 или ACT/365F). Время модели — ACT/365F от даты оценки. Защита начинается
в конце дня T (step-in T+1 календарный день, как в ISDA).

**Открытые вопросы спецификации** заведены как настройки (Настройки кредитных кривых → «Прайсинг CDS»),
ответ НКЦ или Сбера меняет параметр, а не код:

* ребейт в примере Мосбиржи 28.10.2026 — 38 или 39 дней: по тексту спецификации (от смещённой CDS-даты
  до E, 38 дней), от несмещённой CDS-даты или с включением E (39 дней);
* защита с Даты начала срока вместо step-in T+1;
* у Сбера: сдвигаются ли концы периодов вместе с датами платежей, включает ли последний период Плановую
  дату прекращения;
* R<sub>q</sub> для конверсии QS ↔ PUF (40%), набор стандартных сроков, календари профилей.

## 4. Формулы

Всё — с позиции покупателя защиты, на единицу номинала. P(t) — DF, Q(t) = exp(−∫λ) — дожитие.

**Защитная нога** (выплата 1 − R в момент дефолта):

V<sub>prot</sub> = (1 − R) ∫ P(t) λ(t) Q(t) dt по [начало защиты, Плановая дата прекращения].

**Премиальная нога** (RPV01, «рисковая аннуитет»):

RPV01<sub>dirty</sub> = Σ<sub>i</sub> α<sub>i</sub> P(pay<sub>i</sub>) Q(end<sub>i</sub>) + AoD<sub>i</sub>,
AoD<sub>i</sub> = ∫ α(t) P(t) λ(t) Q(t) dt по периоду — накопленный купон, который платится при дефолте.

λ и форвардная ставка f = −d ln P / dt кусочно-постоянны, поэтому интегралы считаются точно: на [a, b]
с μ = λ + f и Δ = b − a

* ∫ P λ Q dt = Q(a) P(a) λ/μ · (1 − e<sup>−μΔ</sup>),
* ∫ α(t) P λ Q dt = Q(a) P(a) · [α<sub>a</sub> λ/μ (1 − e<sup>−μΔ</sup>) + κ λ (1 − e<sup>−μΔ</sup>(1 + μΔ)) / μ²], κ — прирост α за год.

**Цена**:

* PV<sub>dirty</sub> = V<sub>prot</sub> − c · RPV01<sub>dirty</sub> — стоимость контракта на дату оценки;
* RPV01<sub>clean</sub> = RPV01<sub>dirty</sub> − α<sub>rebate</sub> · P(settle);
* **par spread** = V<sub>prot</sub> / RPV01<sub>clean</sub>;
* **PUF** (чистый upfront, % номинала, плюс — платит покупатель) = PV<sub>dirty</sub> / P(settle) + c · α<sub>rebate</sub>;
* **первоначальный платёж** = (PUF − c · α<sub>rebate</sub>) · N, расчёты T+1 р.д.; ребейт c · α<sub>rebate</sub> · N
  платит продавец.

**QS ↔ PUF** (конвенция ISDA): QS — котировка спредом. Котировки связывает плоская кривая интенсивности λ<sub>q</sub>
с recovery R<sub>q</sub> = 40% на дисконт-кривой RUB даты CDS-кривой:

* QS → PUF: λ<sub>q</sub> такая, что par spread плоской кривой равен QS; PUF — upfront на этой кривой при купоне контракта;
* PUF → QS: λ<sub>q</sub> такая, что upfront при купоне контракта равен PUF; QS — par spread этой кривой.

λ<sub>q</sub> ищется методом Брента на [10<sup>−10</sup>; 5]; если корня нет (например, продавец «доплачивает» больше,
чем позволяет λ > 0), котировка вне допустимого диапазона. QS > купона ⇔ PUF > 0 (платит покупатель); QS = купону ⇔
PUF = 0. QS ≠ par spread: у par spread — модельная кривая и R контрольного лица.

**NPV в калькуляторе**: если задан upfront сделки или заявки (PUF), NPV = знак · N · P(settle) · (PUF<sub>модели</sub> − PUF<sub>сделки</sub>);
иначе — знак · N · PV<sub>dirty</sub> (контракт без upfront по заданному купону). У Сбера с документационным базисом
кривая перед расчётом перестраивается по par spread + базис; так же — если в калькуляторе задан другой recovery.

## 5. Календари рабочих дней

Справочник «Календари рабочих дней» (меню кредитного раздела): календарь хранит только **исключения** —
нерабочие будни и рабочие выходные, остальные будни рабочие. Календарь может наследовать другой: СПФИ =
Москва + собственные исключения (дни без клиринговых сессий). При первом запуске созданы пустые календари
«Москва» и «СПФИ»: **праздники нужно внести** (клик по дню), иначе рабочими считаются все будни.
Изменения пишутся в журнал; калькулятор сдвига на N рабочих дней — на той же странице.

## 6. Интерфейс

* **CDS-кривые** — список контрольных лиц с par spread / PUF на 1Y, 3Y, 5Y, датой и причиной последнего
  пересчёта; кнопка «Файл для position keeping»; добавление контрольного лица (код, название, ИНН/ОГРН/LEI,
  контрольное обязательство, кредитная кривая, стандартный купон, максимальный срок, recovery, базис b(T),
  документационный базис Сбера).
* **Контрольное лицо** — котировки по срокам (par из облигаций, базис, par spread, QS, PUF 100/500, дожитие,
  RPV01, λ участка), графики спредов и интенсивности/дожития (CDS и облигации), график платежей
  стандартного контракта любого срока с ребейтом; история по датам и версиям.
* **Калькулятор CDS** — любой контракт на кривой контрольного лица: профиль, дата кривой и сделки, срок или
  дата, купон, номинал, сторона, цена сделки, recovery → par spread, PUF, QS, NPV, ребейт, первоначальный
  платёж, вероятность дефолта, график платежей. Цену сделки или заявки СПФИ можно ввести как **QS** или как
  **upfront (PUF)** — второе считается автоматически при вводе (`POST /api/credit/cds/calculator/quote`) и
  пересчитывается при смене срока, купона или дат; под полями — upfront в рублях, первоначальный платёж с ребейтом
  и λ<sub>q</sub>. В Excel контракта на листе «Итог» — обе котировки и λ<sub>q</sub> с пометкой, какая введена.

## 7. Детализация в Excel

Кнопка **Excel** у CDS-кривой (текущей и исторической) и в калькуляторе. Файл пересчитывает результат
живыми формулами, у ключевых ячеек есть комментарии:

| Лист | Что |
|---|---|
| Итог | параметры, результат по срокам (кривая) или контракта: par spread, PUF, QS, ребейт, NPV — формулами от листов ниже, с ячейками-проверками против значения сервиса |
| Кривые | узлы λ и DF; DF и Q на любую дату — формулами (лог-линейная интерполяция DF, кусочно-постоянная λ) |
| График | периоды: начало, конец, дата платежа, α по ACT/ACT, DF, Q, α·DF·Q, AoD |
| Интегралы | разбиение каждого периода по узлам λ и DF и замкнутые формулы защитной ноги и AoD на каждом куске |

Проверки (столбец «Расхождение») подсвечиваются красным при отклонении больше допуска (10<sup>−8</sup>,
для процентов и рублей 10<sup>−6</sup>); на тестовых данных расхождения ~10<sup>−13</sup>.

## 9. Сделки и их оценка

Меню «Сделки CDS» — ввод, поиск и оценка сделок (`credit_service/cds/trades.py`, `schedule.py`).

**Ввод** (оператор): External ID — для сопоставления с той же сделкой во внешних системах (уникален), контрольное лицо,
сторона (покупка или продажа защиты), номинал, купон (100 б.п. или свой), дата сделки, дата экспирации, ребейт,
расписание, теги и комментарий. Дата начала срока по умолчанию — T + 1 рабочий день с ребейтом и T без него; её можно задать.
Кнопки 6M…10Y у даты экспирации ставят стандартный срок: даты CDS (от даты начала срока к ближайшему 20.06 или 20.12
+ срок) для стандартного расписания, дата начала срока + срок — для своего.

* **Ребейт**: первый купон платится за весь купонный период (с предыдущей даты купона), а накопленное с начала периода до
  даты начала срока продавец возвращает при расчётах. Без ребейта первый период начинается с даты начала срока.
* **Расписание**: стандартные даты CDS (20.03/06/09/12, «Следующий», даты периодов сдвигаются вместе с платежами) или
  своё — как у ноги процентного свопа: частота 1/3/6/12 мес., генерация назад от экспирации (неполный период в начале)
  или вперёд от начала срока (в конце), короткий или длинный неполный период, день ролла, перенос дат (Следующий,
  Модифицированный следующий, Предыдущий, без переноса), сдвиг дат периодов вместе с платежами, календарь, коэффициент дней,
  включение даты экспирации в последний период. Стандартный режим с ребейтом даёт ровно график СПФИ, без ребейта — Сбера.
* **График** строится автоматически и редактируется: начало первого периода, концы периодов (начало следующего сдвигается),
  даты платежей, суммы купонов; объединение периода со следующим. Суммы следуют за датами (α · N · c), пока их не ввели
  вручную. Если в графике есть ручные правки, а условия поменялись, график не перегенерируется молча — система предупреждает
  и предлагает «Сформировать заново».
* **Теги**: подсказки из базы при вводе (с числом сделок), новый тег сохраняется вместе со сделкой; регистр не важен.
* **Версии**: каждое сохранение — новая версия (условия, график, теги); аннулированная сделка не оценивается, её можно
  восстановить. Всё пишется в журнал изменений.

**Теоретическая стоимость на дату D** (со стороны сделки): берётся CDS-кривая контрольного лица — последняя рассчитанная
не позже D — и переносится на D (дожитие условно на отсутствие дефолта до D, дисконт-факторы DF(D, ·) = DF(C, ·)/DF(C, D));
остаток контракта оценивается по модели ISDA на собственном графике сделки:

* NPV = знак · N · (V<sub>prot</sub> − c · RPV01<sub>dirty</sub>);
* накопленный купон — с начала периода, содержащего дату step-in (D + 1), по ISDA; чистая стоимость = NPV − накопленный купон;
* par spread остатка контракта, RPV01, CS01 ≈ знак · N · RPV01 · 1 б.п., вероятность дефолта до экспирации, ближайший купон.

**Когда считается и сохраняется** (каждый расчёт — новая запись; значение даты — последний расчёт этой даты):

| Событие | Что |
|---|---|
| сохранена сделка (новая версия), восстановлена | стоимость на сегодня |
| пересчитана CDS-кривая контрольного лица — после сохранения кредитной или процентной кривой, изменения контрольного лица, кнопки «Пересчитать» | стоимость его сделок на сегодня (задача `credit.trades_revalue`) |
| CDS-кривая изменена задним числом на дату D | стоимость на D |
| конец рабочего дня (`credit.trades_eod`, 23:45, календарь «Москва») | итог дня по всем действующим сделкам |
| «Оценить на дату» / «Оценить сейчас» | на выбранную дату, в том числе прошлую |

Сделка оценивается, пока дата сделки ≤ D ≤ даты экспирации; до появления первой CDS-кривой контрольного лица оценки нет.

**Интерфейс**: список сделок с оценкой на дату (по умолчанию сегодня, кнопка «пред. рабочий день» с датой в подсказке),
поиск по External ID и комментарию, фильтры по контрольному лицу, тегам (все выбранные), стороне и статусу, итоги
NPV и CS01; карточка сделки — показатели последней оценки, график и таблица значений по датам (переключатель «все
расчёты внутри дня»), условия, график платежей, версии.

API: `/api/credit/cds/trades` (Swagger — `/api/credit/docs`).

## 10. Сознательные упрощения

* Сделки вводятся вручную; загрузки из внешних систем нет (External ID — для сверки). Upfront сделки не хранится:
  теоретическая стоимость — стоимость оставшегося контракта.
* Рыночные котировки CDS (уровни 1–2 спецификации) не загружаются: кривая всегда из облигаций + базис.
  Бутстреп по рыночным котировкам в модуле есть (`isda.bootstrap`), его можно подключить, когда появится
  источник.
* Одна валюта (RUB) и один уровень приоритета (старший долг), как у кредитных кривых.
